v44 배포 전 최종 점검 및 수정

적용 방법
1. 아래 세 파일을 현재 프로젝트의 같은 이름 파일에 덮어씁니다.
   index.html
   script.js
   service-worker.js
2. style.css는 이번에 첨부한 최신 파일을 그대로 사용합니다.
3. routine-components.js는 앞 단계에서 이미지 확대를 적용한 파일을 그대로 사용합니다.
4. exercise-data.js, manifest.json, images 폴더도 그대로 사용합니다.
5. 저장 후 Cursor 미리보기에서 확인하고 커밋/푸시합니다.

버전 설정
index.html의 style.css, exercise-data.js, routine-components.js, script.js 주소를 모두 v44로 맞췄습니다.
service-worker.js도 APP_VERSION = "44"로 맞췄습니다. 이번에는 버전을 추가로 수정하지 않아도 됩니다.
다음 배포부터는 index.html 네 곳의 ?v=숫자와 service-worker.js 맨 위 APP_VERSION 숫자를 함께 변경합니다.
서비스워커의 자원 주소와 캐시 이름은 APP_VERSION을 따라갑니다.

커밋명 추천
v44 휴식 타이머·이미지 확대 및 배포 안정성 개선

최종 점검 결과
- 첨부 HTML은 v42, 첨부 서비스워커는 v43으로 버전이 서로 달랐습니다. 모두 v44로 통일했습니다.
- CSS는 휴식 타이머까지 적용한 최신 전달본과 일치했습니다. 이번 점검에서 CSS 수정은 하지 않았습니다.
- HTML ID 중복, 정적 JavaScript 요소 참조 누락, label/ARIA 연결 오류를 발견하지 못했습니다.
- CSS 괄호 구조와 변수 참조, 숨김 규칙, 타이머/확대창/관리자 입력 영역의 주요 규칙을 점검했습니다.
- 서비스워커는 앱 경로별로 캐시 이름을 구분하고, 현재 앱의 예전 캐시만 정리하도록 보완했습니다.
- v43 이전 캐시는 포함된 주소가 모두 현재 앱 경로에 있을 때만 삭제합니다. 다른 앱/혼합 캐시는 유지합니다.
- 외부 Supabase와 다른 프로젝트의 요청은 서비스워커 처리 대상에서 제외합니다.
- 오프라인에서는 현재 버전 캐시를 우선 확인하고, 페이지 요청이면 현재 버전 index.html로 대체합니다.
- 캐시 저장 실패는 정상 네트워크 응답을 막지 않도록 했습니다.
- 네트워크와 캐시가 모두 없을 때도 정의된 오류 응답을 반환하도록 했습니다.
- 현재 HTML/코드에서 사용하지 않는 images/routine-guide.png는 필수 캐시 목록에서 제외했습니다. 실제 파일을 삭제하는 작업은 아닙니다.

함께 포함한 이전 점검 수정(script.js)
- 문의 목록은 가장 최근 요청의 결과만 반영합니다.
- 자동 갱신 실패 시 기존 회원 문의 목록과 입력 내용을 유지합니다.
- JSON 루틴 편집 시 불필요한 옛 이미지 주소 조회를 건너뜁니다.
- 휴식 타이머와 관리자 입력 방식 구분도 포함되어 있습니다.

검증 범위
코드 문법, HTML/CSS 연결 구조, 요청 경합, 캐시 설치/갱신/오프라인/오류 처리와 기존 주요 기능을 모의 환경에서 검증했습니다.
실제 운영 서버의 파일 응답, Supabase 권한/트리거, 모바일 브라우저 렌더링을 직접 검증한 것은 아닙니다.
외부 Google Drive 이미지, YouTube, Supabase 기능까지 오프라인으로 작동하도록 만드는 변경은 아닙니다.
로그인 저장소를 삭제하거나 로그아웃시키는 코드는 추가하지 않았습니다.

배포 후 짧게 확인
- 앱을 새로고침하여 운동 구성에서 타이머 표시와 이미지 확대 확인.
- 센터 커뮤니티로 옮기면 타이머가 숨겨지는지 확인.
- 관리자에서 JSON/이미지 루틴 회원을 선택하여 입력 방식 확인.
- 문의 필터 전환과 답변 표시 확인.
