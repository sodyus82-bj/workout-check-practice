배포 전 중간 코드 점검

점검 기준
- 마지막으로 전달한 휴식 타이머 버전의 index.html / style.css / script.js
- 마지막으로 전달한 기구 이미지 확대 버전의 routine-components.js
- 기존 exercise-data.js
사용자가 이 파일들 이후 별도로 수정한 내용과 실제 운영 DB 설정은 포함하지 않습니다.

교체 방법
압축파일의 script.js 한 개만 프로젝트의 같은 이름 파일에 덮어씁니다.
index.html, style.css, routine-components.js, exercise-data.js는 현재 파일을 유지합니다.
Supabase SQL 변경은 없습니다.

발견 및 수정
1. 문의 목록의 오래된 응답이 최신 화면을 덮는 문제
   - 관리자 문의 필터를 빠르게 바꿀 때 이전 필터의 응답이 늦게 도착하면 최신 목록을 덮을 수 있었습니다.
   - 회원 문의 목록도 조회가 겹칠 때 같은 가능성이 있었습니다.
   - 요청마다 번호를 붙이고 현재 화면/필터/표시 개수를 확인한 결과만 반영합니다.
   - 이전 요청의 오류와 완료 처리도 새 요청의 안내문이나 버튼 상태를 바꾸지 못하게 했습니다.
   - 문의 구독을 종료할 때 진행 중인 목록 요청도 무효화합니다.

2. 회원 문의 자동 갱신 실패 시 목록이 사라지는 문제
   - 기존 코드의 오류 처리에서 보고 있던 목록을 비웠습니다.
   - 기존 화면을 유지하는 갱신에서는 목록과 답변 입력 내용을 그대로 두고 오류 안내만 표시합니다.
   - 첫 조회 실패는 기존처럼 오류 메시지를 표시합니다.

3. 관리자 JSON 루틴 편집의 불필요한 이미지 조회
   - JSON만 수정할 때도 예전에 연결된 루틴 이미지 주소를 조회했습니다.
   - 옛 이미지 조회 실패 때문에 JSON 편집까지 막힐 수 있어, JSON 루틴은 해당 조회를 건너뜁니다.
   - 기존 이미지 루틴은 기존 방식으로 불러옵니다. DB의 이미지 자료를 지우지는 않습니다.

검증 결과
- JavaScript 문법 검사 통과.
- HTML ID 중복, 정적 DOM 참조 누락, script.js 최상위 함수 이름 중복 없음.
- 요청 응답 순서를 뒤집은 테스트에서 이전 코드의 덮어쓰기 문제를 재현했고, 수정 후 통과.
- 문의 자동 갱신 실패 시 기존 DOM 유지, 로그아웃 후 늦은 응답 무시 확인.
- 관리자 입력 방식 구분, JSON 검사/저장, 중복 저장 방지, 저장 결과 미확인 시 재시도 차단 확인.
- JSON 루틴에서 기존 이미지 조회가 실패하더라도 편집창이 정상 열리도록 확인.
- 센터 소식 순서 변경/삭제 및 DOM 유지 모의 검사 통과.
- 이미지 확대, DAY 접기/펼치기, 영상 정리, 휴식 타이머 모의 검사 통과.

구조에 대한 판단
현재 점검한 범위에서 새 기능을 배포하기 위해 전체 코드를 재작성할 필요는 없습니다.
script.js와 style.css에 기능이 누적되어 있으므로 향후 기능 추가 시 단위별 분리를 권장합니다.
이번에는 확인된 오류 처리와 비동기 응답 처리만 보완했습니다.

남은 배포 점검
현재 사용 중인 최신 index.html과 service-worker.js의 자원 버전 및 캐시 이름 확인이 필요합니다.
보유한 service-worker.js 업로드는 v37이어서 현재 배포 파일로 간주하지 않았습니다.
실제 모바일 브라우저, 운영 Supabase 권한/트리거, 서비스워커 업데이트는 이번 모의 검사 대상이 아닙니다.

사용자 확인
1. 관리자 문의의 답변 대기 / 답변 완료 / 보관함 전환.
2. 회원 문의 목록과 답변 표시.
3. 관리자에서 JSON 루틴 회원을 선택하고 편집창 표시 확인.
